# План покрытия: по одному небольшому заданию

**Текущее задание: U10.** Зачтены U02, U03, U04, U05, U06, U07, U08 и U09. U01 ожидает повторной сдачи.

Чекбокс отмечается после проверки, а не просто после запуска зелёных тестов.
Обычная карточка — 10–25 минут; первые встречи с async или Cypress могут занять дольше.
Если сложно, разбираем только текущую карточку. В каждой карточке меняются **только тесты, фикстуры
и при необходимости тестовые вспомогательные функции**. Приложение уже реализовано.

Для файлов `*.test.tsx` используются Vitest + RTL; для `*.test.ts` — Vitest;
для `*.cy.ts` — Cypress. Файлы создаются вами по мере прохождения.
Можно дополнять файл предыдущего задания. Smoke-тесты окружения оставьте как есть.

**Приёмка:** суммы проверяются в соответствующих строках итогов, а не где угодно на странице.

### [ ] E05 — Полный успешный заказ

**Файл:** `cypress/e2e/checkout.cy.ts`.

- Добавьте товар, перейдите к оформлению, заполните форму вымышленными данными.
- Настройте alias POST без подмены ответа; отправьте заказ.
- Проверьте HTTP 201, items запроса, видимый номер заказа и пустую корзину.

**Приёмка:** хотя бы этот сценарий проходит через настоящий локальный API целиком.

### [ ] E06 — Ошибка каталога и восстановление

**Файл:** `cypress/e2e/catalog-error.cy.ts`.

- Первый GET через `cy.intercept` отвечает 500.
- Проверьте сообщение ошибки; настройте успешный следующий ответ либо пропустите его в реальный API.
- Нажмите повтор и дождитесь карточек.

**Приёмка:** тест воспроизводим; первый и второй ответы контролируются явно.

### [ ] E07 — Ошибка заказа сохраняет пользовательские данные

**Файл:** `cypress/e2e/order-error.cy.ts`.

- Подмените POST ответом 500.
- После отправки видны сообщение ошибки, прежние поля и товар в корзине.
- Повторный POST успешен, заказ оформляется.

**Приёмка:** тест не зависит от результата E05 и не отправляет запросы внешним сервисам.

### [ ] E08 — Оформление на узком экране

**Файл:** `cypress/e2e/mobile.cy.ts`.

- Установите `cy.viewport(390, 844)`.
- Добавьте товар, прокрутите к корзине, откройте форму.
- Проверьте доступность полей и кнопки, заполните форму и оформите заказ.

**Приёмка:** интерактивные элементы доступны обычным кликом, без принудительного обхода проверок видимости.

## Этап 6. Качество собственных тестов

### [ ] Q01 — Разобрать один пропуск покрытия

**После:** этапов 1–4. **Инструмент:** `.\scripts\run.ps1 test:coverage`.

- Откройте `coverage/index.html`, выберите ровно одну непокрытую ветку.
- Опишите поведение, которое она представляет.
- Добавьте один осмысленный тест, если поведение важно и ещё не проверено.

**Приёмка:** объяснение ценности проверки и осмысленный assertion; цель не «добить процент».

### [ ] Q02 — Убедиться, что тест ловит поломку

**После:** любого зачтённого теста.

- Выберите один свой тест и напишите, какую минимальную ошибку в приложении он должен обнаружить.
- Попросите проверяющего временно внести такую ошибку и проверить падение.
- После восстановления кода повторно запустите тест.

**Приёмка:** зафиксирован цикл зелёный → красный → зелёный. Production-код меняет и восстанавливает
проверяющий; ваша работа — проверить чувствительность теста и при необходимости улучшить assertions.
