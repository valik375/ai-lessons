# Deskshop — практика тестирования

Готовый React + TypeScript магазин. Ваша работа — **писать тесты**, а не реализовывать приложение.
В нём есть отдельные компоненты, чистые функции, взаимодействующие блоки и настоящий локальный HTTP API.
Реальной оплаты нет; используйте вымышленные данные при оформлении.
Все цены, суммы доставки и учебные расчёты указаны в гривнах (UAH, ₴).

## Запуск на этом компьютере

В PowerShell из папки проекта:

```powershell
.\scripts\run.ps1 dev
```

Откройте http://127.0.0.1:5173. Терминал с сервером оставьте открытым.
На этом компьютере скрипт использует встроенный Node.js Codex, потому что системный nvm пока не настроен.
Глобальные настройки не меняются. Если PowerShell запрещает скрипты, используйте для конкретного запуска:
`powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 dev`.

Во втором терминале:

| Команда | Что делает |
| --- | --- |
| `.\scripts\run.ps1 test` | Vitest в watch-режиме |
| `.\scripts\run.ps1 test:run` | Однократный запуск всех unit/integration тестов |
| `.\scripts\run.ps1 test:run src/components/Button.test.tsx` | Только тесты кнопки |
| `.\scripts\run.ps1 test:coverage` | Покрытие; HTML в `coverage/index.html` |
| `.\scripts\run.ps1 cy:open` | Интерактивный Cypress; сервер должен работать |
| `.\scripts\run.ps1 cy:run` | Cypress без GUI; сервер должен работать |
| `.\scripts\run.ps1 e2e` | Сам запускает сервер, выполняет Cypress и останавливает сервер |
| `.\scripts\run.ps1 build` | Проверка TypeScript приложения и E2E, production-сборка |

Перед `e2e` остановите свой dev-сервер: порт 5173 должен быть свободен.
Если Node.js и pnpm доступны в PATH, можно запускать обычные команды `pnpm dev`, `pnpm test:run`, `pnpm e2e`.
Для Cypress на этом компьютере удобнее использовать скрипт: он задаёт локальную папку бинарника `.tools/cypress`.
Для чистой установки: Node.js 24 LTS, pnpm 11.25.0 и `.\scripts\run.ps1 install --frozen-lockfile`.
На другом компьютере без Codex нужен самостоятельно установленный Node.js.

## С чего начать

1. Посмотрите магазин в браузере: добавьте товар, поменяйте количество, примените `DESK10`.
2. Прочитайте [карту проекта и правила поведения](docs/PROJECT.md).
3. Откройте [план из небольших заданий](docs/TASKS.md). Начните с **U01: кнопка — текст и клик**.
4. Создайте файл `src/components/Button.test.tsx`. Готового решения нет.
5. После выполнения напишите в этом чате: **«Проверь U01»**. Файлы уже доступны для проверки.

Задания проходят по одному. Проверка включает запуск тестов, чтение утверждений и оценку того,
заметит ли тест реальную поломку. Процесс описан в [правилах проверки](docs/REVIEW.md).
Не нужно выполнять весь этап, чтобы прислать первый тест.

## Что уже настроено

- Vitest + jsdom, React Testing Library, user-event, jest-dom.
- Очистка DOM, localStorage, глобальных заглушек и таймеров между тестами.
- V8 coverage; пока без порогов, которые мешали бы идти маленькими шагами.
- Cypress E2E с отдельным TypeScript-контекстом: его глобальный `expect` не конфликтует с Vitest.
- Два инфраструктурных smoke-теста. Они подтверждают работоспособность окружения и не являются решениями заданий.
- Никаких `test.todo` или заранее написанных учебных assertions: вы создаёте тесты сами.

При подготовке 20 октября 2026 проверены сборка TypeScript/Vite, smoke-тест Vitest,
генерация coverage и smoke-тест Cypress в Electron. В браузере вручную пройден путь:
добавление лампы → DESK10 → ошибки пустой формы → успешный заказ → пустая корзина.
Это проверка готовности проекта, не зачёт учебных заданий. Cypress пока выводит предупреждение
об устаревании встроенного Electron; установленная версия работает, Chrome можно выбрать в Cypress.

## Документация инструментов

- [Vitest](https://vitest.dev/guide/) и [V8 coverage](https://vitest.dev/guide/coverage.html).
- [React Testing Library](https://testing-library.com/docs/react-testing-library/intro/) и [user-event](https://testing-library.com/docs/user-event/intro/).
- [Установка Cypress](https://docs.cypress.io/app/get-started/install-cypress) и [перехват запросов](https://docs.cypress.io/api/commands/intercept).

API подключён плагином Vite и работает в `dev` и `preview`. Простая публикация папки `dist` без сервера
не предоставит `/api`. Для этого учебного проекта публикация не требуется.
